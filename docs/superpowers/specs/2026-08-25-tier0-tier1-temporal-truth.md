## Goal

After this work, the README's headline claims are either **true and measured** or **not made**. Concretely:
1. The character can say "three weeks ago" because every memory it sees carries a date and it knows today's date.
2. A 60-simulated-day conversation, run through `chat()` with a fake clock and mock LLM, proves paraphrased recall of old memories, decay ordering, contradiction supersession, and relationship drift — and runs in CI.
3. Retrieval considers **all** active memories, not the 200 newest core rows.
4. A chat turn costs **one** bookkeeping LLM call (emotion + relationship + beat + facts), not four.
5. All chat-path prompts live in one registry with ids and versions.
6. Repo hygiene: single benchmark number, no stale files, honest docs.

Out of scope (later tiers): bi-temporal structured facts, relationship state machine, Ebbinghaus decay, drift instrumentation, LoRA distillation, Kotlin parity (Kotlin C1 branch must adopt the new retrieval rule + prompt formats when it merges — noted in CHANGELOG).

## Tier 1 — behavior

### T1.1 Injectable clock (`woven_imprint/clock.py`)
- `now() -> datetime` (UTC, aware). `today() -> date`. `override(value: datetime | Callable[[], datetime] | None)` context manager / setter; `advance(delta: timedelta)` for tests when an override is active.
- `sqlite_ts(dt) -> "YYYY-MM-DD HH:MM:SS"`, `parse_ts(str) -> datetime` (accepts the existing formats, assumes UTC if naive).
- All Python clock reads switch to it: `retrieval.py:61`, `maintenance.py:93`, `callbacks.py:24`, `character.py:222,1035`, `metrics.py:30`, `persona/model.py:36,47,55`.
- Storage writes stamp explicitly: `save_memory` uses `memory["created_at"]`/`["accessed_at"]` when present else `clock.now()`; `MemoryStore.add`/`add_without_embedding` set `created_at` from the clock; `save_session` accepts `started_at`/`ended_at`; `touch_*` use the clock. SQL `DEFAULT (datetime('now'))` stays as fallback. No schema migration.

### T1.2 Dates in the prompt
- `_format_memories` renders `- [core] (2026-05-03, 3 weeks ago) content…`. Relative phrasing via `clock.relative(dt, now)`: `today`, `yesterday`, `N days ago` (<14), `N weeks ago` (<8 weeks), `N months ago` (<12), `N years ago`.
- Volatile block begins with `Today is {weekday}, {YYYY-MM-DD}.` (config `context.include_date: bool = True`).
- Session summaries: stored with `metadata={"type": "session_summary", "started_at", "ended_at"}`; content prefix becomes `[Session Summary {YYYY-MM-DD}]`. Consolidation summaries keep a `metadata["date_range"] = [min_created, max_created]` and their `created_at` is the **latest** source date (not now), so recency reflects the events.
- `reflect()`, growth, maintenance importance/contradiction prompts render `(YYYY-MM-DD)` after each memory line.

### T1.3 Retrieval over all active memories
- Candidate pool = **all** active memories for the character (`get_memories(..., limit=None)` → no LIMIT) ∪ FTS hits. Config `memory.max_candidates: int = 5000` hard cap (newest first if exceeded — documented).
- Semantic scoring: if `numpy` importable, build the matrix once per `retrieve()` (`np.frombuffer` over stored float32 blobs) and score in one matmul; else pure-Python (existing `_cosine_similarity`). `numpy` added as optional extra `woven-imprint[fast]`; CI installs it.
- Same RRF fusion; outputs and `_retrieval_score` semantics unchanged. `consolidation.py` imports the retrieval cosine instead of its copy.
- Kotlin conformance fixtures (`kotlin/conformance/generate_fixtures.py`) are on the unmerged Kotlin branch — CHANGELOG notes the contract change.

### T1.4 One bookkeeping call per turn — `persona/assessment.py`
- `TurnAssessor(llm).assess(message, response, *, character_name, other_name, current_emotion, arc, want_facts: bool, context_hint: str) -> TurnAssessment` with fields `emotion: dict|None`, `relationship: dict|None`, `beat: dict|None`, `facts: list[str]`.
- One `generate_json_robust` call; prompt asks for `{"emotion": {...}, "relationship": {...}, "beat": {...}|null, "facts": [...]}`. Parsing reuses the existing validators, refactored into pure functions: `EmotionEngine.parse_assessment(data, current, character_name) -> EmotionalState`, `ArcTracker.parse_beat(data, arc) -> StoryBeat|None`, `Character._parse_relationship_deltas(data) -> dict`, `Character._parse_facts(data) -> list[str]`. Each engine's standalone method stays and now delegates to its parser.
- `Character._run_subsystems_sequential/_parallel` are replaced by `_run_bookkeeping(...)` when `character.unified_assessment` (new config, default **True**) — one call, then apply results (emotion state, arc mutation, relationship update, fact storage incl. belief revision). When False, the old per-engine path runs unchanged (kept for A/B).
- `want_facts` follows the existing `fact_extraction_interval` throttle; beat detection follows the existing every-2nd-turn rule (the prompt tells the model whether to emit those sections; absent sections parse to None/[]).
- Consistency checker remains a separate hot-path call, default unchanged (`enforce_consistency=True`); README's performance section documents it as the main cost knob.
- Health counters: one new key `"assessment"`, plus per-section failures still counted under their old keys.

### T1.5 Long-horizon benchmark (`eval/bench_longhorizon.py` + `tests/test_longhorizon.py`)
- Deterministic; mock LLM + `FakeEmbedder`; clock overridden; 60 simulated days × 1 session × 3 turns. Scripted `LongHorizonLLM` returns, per turn, a unified assessment (T1.4 schema) whose `facts` contain one unique dated fact string (`"On day N the visitor mentioned <noun_N>"`) and scripted relationship deltas (+trust on days 1–40, −trust on days 41–50 "betrayal", +trust 51–60); nightly `MaintenanceRunner.run_all` with the same LLM (importance scoring / contradiction verdicts scripted).
- Benchmarks (each a `BenchmarkResult`):
  1. `paraphrase_recall_day5`: query built from a different word order / subset of day-5's noun → the day-5 memory is in top-10 after 60 days (this fails today because of the 200-core window).
  2. `dates_rendered`: `_format_memories` output for that retrieval contains `2026-` dates and a `weeks ago`/`months ago` phrase; volatile block contains `Today is`.
  3. `recency_ordering`: for two memories with identical content class, the newer ranks higher.
  4. `contradiction_supersession`: day-10 "The visitor likes tea." vs day-40 "The visitor dislikes tea." → old memory status `contradicted`, retrieval for "tea" returns the day-40 memory first.
  5. `relationship_trajectory`: trust after day 40 > after day 1; trust after day 50 < after day 40; familiarity monotonic; `key_moments` untouched (documented as roadmap).
  6. `session_summaries_dated`: every `[Session Summary` memory has `metadata.started_at` and its content prefix carries the date.
  7. `bookkeeping_call_count`: with unified assessment, LLM JSON calls per turn == 1 (excluding maintenance).
- Wired into `eval/run_eval.py`; `tests/test_longhorizon.py` runs the suite and asserts `failed == 0` (CI gate).

### T1.6 Prompt registry (`woven_imprint/prompts.py`)
- `PromptSpec(id, version, system, user, expects)`; `PROMPTS: dict[str, PromptSpec]`; `render(id, **kwargs) -> list[dict]`. Templates are the **byte-identical** current strings (verified by tests that render with fixed kwargs and compare to the pre-refactor output captured as fixtures).
- Covered sites (18): chat main (assembly stays in `_build_context`; registry holds the header sentences), fact extraction, relationship (turn + event), reflect, session summary, emotion (turn + event), consistency check + retry reminder, growth, arc beat, consolidation summary, callbacks hooks + compose, maintenance importance + contradiction, context compression, plus the new unified assessment.
- `woven-imprint prompts` CLI subcommand lists ids/versions (cheap, useful for model tuning).
